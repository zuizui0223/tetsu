# Photo ROI and flowering-phenology input contract

**Outputs are descriptive and synthetic tests are not field results.** See [full theory and study plan](rail_environment_traits_protocol.md).

## ROI masks

Input CSV columns:
- `image_id,site_id,taxon,photo_date,photographer_id,site_class,whole_plant,standardized_view,phenophase,plant_mask,flower_mask`
- `site_class` = `rail`, `road`, `background` or `unknown`.
- `whole_plant`, `standardized_view` are booleans `true/false`.
- `target_scope` one of `individual`, `patch`, `closeup`, `unknown`. `mask_reviewed` is `true/false`: independently reviewed alignment and target identity, not simply generated by an algorithm. Only reviewed **individual** targets can have `valid_for_cross_image_shape_comparison=true`. Patch/close-up features stay `restricted` even if pixel ratios are returned.\n- `phenophase` one of `unknown`, `vegetative`, `bud`, `flowering`, `fruiting`, `flowering_fruiting`.
- Mask filenames resolve inside `--root`; 8-bit PNG masks (0 = background, > 0 = foreground), *same dimensions and aligned*. `plant_mask` must include flower pixels; pixels outside it trigger rejection.
- A blank `flower_mask` means **flower region not annotated**, *not* that the plant is not flowering. A supplied all-black flower mask means explicitly annotated no visible flowers. Phenophase is an independent label and quality control.
- If photo is close-up, clipped at image border, multi-individual patch, unreviewed mask or unstandardized view, geometry can be retained as diagnostic but is marked `restricted`, not valid for across-photo plant shape comparison.
- Image license, source link, observer, GPS accuracy and segmentation confidence should be retained in a separate provenance table in real projects.\n- **Fixed plot vegetation patch ROI** now has *optional* metadata: `plot_id` (stable independently confirmed plot), `fixed_plot_view=true`, and `same_taxon_patch=true`, alongside `target_scope=patch`, `mask_reviewed=true`, `standardized_view=true`, and an explicitly supplied floral PNG mask. Only then is `valid_for_fixed_plot_flower_fraction=true` with `quality_status=patch_pass`. This allows visible floral display per conspecific vegetation pixels from repeated quadrat photographs, **not individual plant height, biomass, or absolute size**. All inputs must be confirmed independently; inferred rail distance does not establish a railway verge.\n- A patch is never eligible for `valid_for_cross_image_shape_comparison=true` even when its flowering ROI fraction is valid. Patch area may touch the frame boundary because the quadrat is fixed; patch fraction still needs known stable framing and an annotation of *all* target-species greenery and visible flowers.

Run:
```bash
pip install Pillow
python scripts/extract_photo_roi.py --manifest my_photo_manifest.csv --root /path/to/masks --output results/photo_roi.csv
```

Do not translate plant occupancy fraction into true height, plant biomass, plant size or wind adaptation. Even whole-plant aspect ratio and solidity vary with view angle and occlusion. Prefer within-species, independently matched photos or standardized fixed-point surveys.

## Structured flowering visits (not opportunistic first bloom dates)

Input CSV `visits.csv`:
```csv
visit_id,site_id,taxon,obs_date,site_class,phenophase,survey_complete,observer_id,effort_minutes
v1,rail_01,Fictitia exemplaris,2026-06-01,rail,vegetative,true,o01,12
v2,rail_01,Fictitia exemplaris,2026-06-15,rail,flowering,true,o01,12
v3,road_01,Fictitia exemplaris,2026-06-15,road,bud,true,o01,12
```

- One row per taxon for each **complete site survey**. `survey_complete` = whether that species was assessed and not selectively reported. If surveying different plants each week, this is **not** proof of repeated individuals.
- A species not mentioned in an iNaturalist/GBIF photo set is **not** a verified nonflowering visit; enter `survey_complete=false` or `phenophase=unknown`. No zero imputation.
- Standardized `obs_date` and explicit observer; species names illustrative, not present in actual data.

Optional verified management `events.csv`:
```csv
site_id,event_date,event_type,evidence
rail_01,2026-06-08,cutting,operator_work_log
road_01,2026-06-09,herbicide,municipal_notice
```
- Only documented `cutting` produces `days_since_verified_cut`. For unknown events/locations, leave this numeric exposure blank (not zero). Evidence must be grounded, not guessed from rail-line presence.
- Other supported management types: `herbicide`, `steam`, `sheeting`, `mulching`, `unknown`.

Run:
```bash
python scripts/summarize_photo_phenology.py --visits visits.csv --events events.csv --output-dir results/phenology
```

Output:
- `eligible_visits.csv`: structured observations + DOY/week/recorded cutting lag.
- `weekly_observed_flowering.csv`: proportion with visible flowers by taxon, site class and ISO week, with numbers of visits and **unique sites**. Low replication (<5 visits or <3 sites) is marked `screening_only=1`. These heuristic thresholds do not establish inferential power.
- `audit.json`: exclusions and a warning that the calculation cannot estimate true onset or claim adaptation.

Before fitting a treatment model, build climate/GDD covariates, within-site pre/post-cut repeated sampling, observer and geographic stratification, and bias-adjusted site- or region-blocked validation. This script deliberately does not report treatment effects or p-values.
